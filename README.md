# 个人保险助手

一个面向个人用户的多保险公司资料分析与测算项目。上传保险条款、产品说明书、费率表和现金价值表后，可以用自然语言查询资料、查看原表、按个人条件生成年度利益表，并比较不同产品的已有分析结果。

项目采用本机部署，目前处于开发与验证阶段。已支持的业务流程由应用内 Agent 自动调用工具完成，实际可用能力取决于资料、执行规则和外部服务状态。

## 项目背景

了解一款保险，往往需要在条款、说明书和多张表格之间反复查找。同一个问题还可能涉及年龄、性别、交费期限、保险年度和金额单位，不同产品的口径也未必一致。

本项目将资料整理、证据检索、条件收集、精确查表、规则计算和结果展示连接起来，让用户可以围绕同一份资料持续咨询。模型负责理解问题、选择工具和组织说明；个人测算金额由程序依据来源数据和已验证规则计算，并保留原件、页码、表格位置与执行条件，便于复核。

## 可以做什么

| 功能 | 使用方式 |
|---|---|
| 资料接入 | 上传 PDF，后台自动准备原文、表格、索引、规则、案例和资料包，展示进度与缺口。 |
| 原文问答 | 查询保险责任、免责、交费等内容，查看原文引用及 PDF 页码。 |
| 原表与案例阅读 | 查看原始表格、单元格及上下文，阅读官方资料中的案例。 |
| 个人测算 | 提供必要个人条件，精确查表、执行已就绪规则，生成年度利益表。 |
| 多轮续算 | 补充缺失条件，修改保费等条件后重新计算，继续历史分析。 |
| 比较与候选整理 | 比较已有分析，结合个人需求整理产品候选、理由和待确认项。 |
| 画像与记忆 | 保存任务条件和个人偏好，支持冲突澄清、更正与忘记。 |
| 结果保存 | 查看历史结果、下载 CSV，在授权本地目录读写 Markdown/CSV。 |

资料准备可能部分完成。例如，一款产品可以回答条款问题，但尚不能进行个人测算。系统分别报告问答和各项测算能力；缺少条件时追问，缺少证据时保留缺口。

## 如何使用

1. 打开助手，选择已有产品资料，或进入上传页面提供保险原件。
2. 等待资料准备完成，查看当前可用能力及缺失项。
3. 用自然语言提出问题；需要个人测算时，按提示补充年龄、性别、交费期限、保费等必要条件。
4. 查看回答、结构化表格和来源引用，按需打开原件核对或下载结果。
5. 继续补充条件、修改方案，或要求比较已有分析。

可以尝试的问题：

- “这款产品的保险责任和免责条款分别是什么？请给出原文出处。”
- “我想按年交一万元查看前五年的基本保额，先确认这份资料能否计算，还缺哪些条件。”
- “沿用刚才的其他条件，把年交保费改为两万元重新计算。”
- “比较刚才两款产品已有的结果，说明条件和指标是否一致。”
- “把这次结果保存为 CSV。”

Agent 根据会话上下文选择工具并组织检索问题。当前没有独立且完成专项验收的查询改写模块，含糊的产品指代或条件仍可能需要补充说明。

|---|---|---|
| 自然语言助手 | http://127.0.0.1:8792/ | 提问、补充条件、查看结果和历史。 |

| 资料上传 | http://127.0.0.1:8792/product-upload | 上传原件，查看准备进度和资料状态。 |

## 本机安装与启动

### 环境要求

- 建议使用已验证的 Python 3.12；项目声明 Python 3.10 或以上，依赖见 [pyproject.toml](pyproject.toml)。当前主要在 Windows 本机环境验证。
- 可连接的 PostgreSQL 和 OpenSearch。
- 对话、向量嵌入和重排服务凭据。当前接入 DeepSeek 对话服务及百炼/DashScope 嵌入、重排服务。
- 需要分析的保险 PDF 原件，扫描件还需要 OCR 依赖。

这是需要配置数据库、检索和模型服务的开发项目，尚未提供一键安装包。以下步骤从空环境准备服务。可以使用仓库内的 Docker Compose，也可以连接自行部署的 PostgreSQL 和本机 OpenSearch。

### 安装依赖

在项目根目录执行：

~~~powershell
python -m venv .venv
.venv/Scripts/python.exe -m pip install -e ".[agent-loop,indexing,ocr,excel,test]"
~~~

### 配置服务

首次配置时可执行 `Copy-Item .env.example .env`；已有 `.env` 时不要覆盖。

首次配置时，将 [.env.example](.env.example) 复制为本机的 `.env`，填写以下内容；已有配置时只补充所需字段。

| 配置 | 用途 |
|---|---|
| `INSURANCE_POSTGRES_DSN` | PostgreSQL 数据库连接。 |
| `DEEPSEEK_API_KEY` 及相关模型配置 | Agent 对话与资料分析。 |
| `DASHSCOPE_API_KEY` 及相关模型配置 | 向量嵌入与检索重排。 |
| `INSURANCE_POSTGRES_PASSWORD` | 使用内置 Compose 时设置数据库密码，需与 DSN 中的密码一致。 |
| `INSURANCE_OPENSEARCH_URL` | 本机检索地址，默认 `http://127.0.0.1:9200`。 |
| `INSURANCE_OPENSEARCH_USER` / `INSURANCE_OPENSEARCH_PASSWORD` | 连接启用认证的本机 OpenSearch 时填写；内置 Compose 默认不启用认证。 |
| `INSURANCE_AGENT_API_TOKEN` | HTTP 业务接口认证，与模型密钥分别配置。 |
| `INSURANCE_LOCAL_FILES_ROOT`（可选） | 本地文件工具可操作的目录，默认使用项目内 `local_files/`。 |

实际密钥保存在本机配置中，避免提交到版本库。资料解析、问答和测算会调用所配置的外部模型服务，使用前应确认资料适合发送至这些服务。

### 准备数据库与检索服务

使用内置 Compose 时，先安装并启动 Docker Desktop，在 `.env` 中设置 `INSURANCE_POSTGRES_PASSWORD`，并将 `INSURANCE_POSTGRES_DSN` 配为同一数据库的连接串（数据库 `insurance_rag`、用户 `insurance`、本机端口 5432；密码中的 URI 特殊字符需编码）。然后执行：

~~~powershell
docker compose --env-file .env -f deploy/stage_two/compose.yaml up -d --wait
~~~

Compose 将 PostgreSQL 与 OpenSearch 仅映射到本机，OpenSearch 使用 9200 端口。若这些端口已有其他服务，请先核对部署和连接配置。已有数据库需要授予应用账号创建 schema、表及索引的权限；首次访问时程序会创建当前业务所需结构，无需导入旧数据库。

### 启动页面

在两个终端中分别执行：

~~~powershell
.venv/Scripts/python.exe scripts/serve_agent.py --port 8792 --local-test
~~~

~~~powershell
.venv/Scripts/python.exe scripts/serve_products.py --port 8793
~~~

然后打开 http://127.0.0.1:8792/ 。服务绑定本机地址，`--local-test` 用于本机测试会话。修改运行代码后，需要重启对应服务。

模型调用会产生服务商费用。主业务循环默认每个任务累计 token 上限为 500000，可通过 `INSURANCE_LOOP_MAX_TOTAL_TOKENS` 调整；辅助画像提取消耗单独记录并受独立调用限制，该参数不代表全应用的总费用上限。

## 能力边界

个人金额仅在来源、条件及执行绑定就绪时生成。固定案例保留原条件，不能直接缩放为个人预测；未决规则、缺失值和未知资格保留在结果中。比较需检查条件与指标口径，候选推荐不代表承保资格确认。

自动执行范围取决于所提供资料、必要条件及执行规则是否就绪。模型、数据库和检索服务需要保持可用；遇到缺少证据、未支持的资料结构或外部服务故障时，任务可能需要补充信息、重试或人工处理。

以下能力尚未完成或未纳入当前范围：

- 官方资料联网获取、周期性自主记忆整理。
- 日期与年龄等规则语义的专项完善。
- 医疗保费、理赔测算及复杂医疗整单分析。
- 陌生产品与版式的充分泛化验证、长期运行及全面故障恢复验证。

## 技术结构

项目基于 Python 与 FastAPI，使用原生 Agent 工具循环编排业务。PostgreSQL 保存任务、结构化分析和个人数据，OpenSearch 支持原文混合检索；金额计算从来源表格和规则取值，保留可追溯关系。

以下源码目录均位于 `src/insurance_rag/`：

| 目录 | 内容 |
|---|---|
| `agent/`、`tools/` | Agent 主循环、上下文、画像记忆及业务工具。 |
| `parsing/`、`ingestion/` | PDF/OCR、表格、资料准备、规则案例及个人执行。 |
| `indexing/`、`retrieval/` | 索引、混合检索、重排及证据上下文。 |
| `api/` | 页面与 HTTP 接口。 |
| `workspace/`、`workflow/` | 授权本地文件与分析存储。 |

项目根目录的 `scripts/` 保存服务启动和诊断入口，`tests/` 保存回归测试。安装和运行说明集中在本 README 中。

运行离线检查：

~~~powershell
.venv/Scripts/python.exe -X utf8 scripts/check.py
~~~

离线检查不验证外部服务连通性，也不能替代真实业务验收。

## 分发与运行条件

仓库包含应用源码、HTML 页面、业务工具、后台 worker、测试、解析配置、依赖声明和 Docker Compose。默认业务使用在线嵌入和重排服务，不需要额外下载本地大模型；可选本地嵌入适配器需要另装 `embedding` 依赖并准备模型文件。OCR 模型由所安装的 RapidOCR 包提供。

使用者需要配置自己的服务凭据，并提供有权使用的保险原件。首次部署从空资料库开始，索引、资料包和执行产物由上传准备流程生成。完成依赖安装、服务配置和资料准备后，即可使用相应资料支持的问答、测算、比较和文件功能。

本项目依赖外部数据库、检索和模型服务，尚未提供完整离线业务演示模式。
