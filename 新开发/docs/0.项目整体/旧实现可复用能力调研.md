> 状态：现行（调研记录）

## 范围与结论

本报告依据旧项目说明、关键源码入口及评测指南进行静态抽样，未运行旧系统、访问旧数据库、外部服务或受限历史数据目录。旧项目为 Python/FastAPI、PostgreSQL 和 OpenSearch；现行使用 Python 后端、TypeScript 前端、Pi、Skill 和 MySQL。以下“复用”主要指业务知识、契约、测试方法和可评估的算法，不代表可直接迁移或已证明当前可用。旧实现文档中的状态仅描述旧项目，不能作为新项目验收结果。

优先研究文档解析及来源定位、表格映射与未决状态、计算输入输出和评测资产。旧模块的直接接入以用户确认范围为准。

## 与新方向的衔接建议

1. 先细化统一产品、版本、文档、证据和资料状态的领域契约，以及业务场景和优先级；不将旧库表直接作为新模型。
2. 选取经授权的真实原件建立小规模、可复核的解析和计算样本；比较旧方案思路和 适用的成熟工具。保留原文定位、未决项和失败案例。
3. 围绕产品查询、证据检索和确定性计算设计后端接口及 Skill 调用契约；Pi 的会话、上下文和技能机制先以实际 SDK 能力验证，避免复制旧 Agent loop。
4. 将来源核验、独立答案、计算样例与语义复核纳入评测设计；记录样本范围及未执行项，不沿用历史通过数。
5. 官网发现、匹配和采集作为目标方向保留；已获授权作为首轮目标；实施前仍需验证网站现状、适配成本和覆盖情况。

首批业务场景和险种、数据源及授权范围、统一 ID 与版本语义、原件与结构化数据的具体存储设计、OCR/复杂表格技术、向量检索选型、计算范围、评测样本及里程碑均待细化。调研未核查 Pi SDK 当前接口或第三方库表现；实际选型前应验证。
