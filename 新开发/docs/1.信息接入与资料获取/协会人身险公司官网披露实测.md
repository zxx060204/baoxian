# 协会人身险公司官网披露实测

> 状态：现行的样本实测记录；不代表全量覆盖或已完成接入。  
> 实测日期：2026-11-11（北京时间）。

用户已确认拥有协会信息披露系统对应的数据提取权限。本次仅只读请求栏目与三家公司详情，未批量采集、未写入公司库。

## 结论

在[协会信息披露系统](https://icidp.iachina.cn/?columnid_url=201509301401)的“互联网保险信息披露 → 人身险信息披露”，可以通过正常会话直接请求栏目和公司详情。三家样本详情均返回 HTTP 200，存在单独的“公司官网链接”和“机构信息披露网站地址”字段。

| 披露机构全称 | 公司官网链接（原始披露值） | 机构信息披露网站地址（原始披露值） |
| --- | --- | --- |
| 国民养老保险股份有限公司 | www.guominpension.com | https://www.guominpension.com/informationDisclosure?id=1422442836213735425 |
| 瑞众人寿保险有限责任公司 | https://www.ruiinsurance.com/ | https://www.ruiinsurance.com/information/base/company/baseInfo.html |
| 中国平安人寿保险股份有限公司 | https://life.pingan.com/index.html | https://life.pingan.com/index.html |

这些是协会系统当前返回的字段，不代表目标网站此刻可访问、信息一定最新，或四类资料均可获取。此前公司库的瑞众和国民养老地址是招聘站；本次未修改它们，差异应进入后续人工确认与修正流程。

## 实测方法与限制

- 页面自行生成客户端标识并发起验证状态请求；按页面流程建立会话、发送该标识和时间戳后，状态返回 `success`，未遇人机验证挑战。
- “互联网保险信息披露”栏目下的“人身险信息披露”可以读取公司列表；依据页面列出的公司名称及入口标识，请求三家详情。栏目列表和详情页面包含 GBK 编码内容，栏目 JSON 使用 UTF-8；应根据响应的 Content-Type 字符集解码。
- 此前省略正常页面使用的客户端标识和请求头时，栏目请求得到 HTTP 404；加上正常页面会话后返回 200。本次验证证明在本次条件下正常请求有效，不能断言请求头是导致此前所有 404 的唯一原因。
- 本次只核查三家样本，没有确认全部公司均有对应字段、披露值的更新频率、网站覆盖率、分页或并发能力；遇人机验证时应停止并由用户处理，不绕过验证。
